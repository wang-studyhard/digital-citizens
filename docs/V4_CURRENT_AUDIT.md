## 4. 公开页实测问题

### P0：案例图片在线失效

`public/media/manifest.json` 使用 `/media/editorial/...` 绝对路径。GitHub Pages 部署在 `/digital-citizens/` 子路径，浏览器因此请求站点根目录，案例区出现“图片暂时无法加载”。本地根路径环境不暴露此问题。

处理：实现批次中改为由 Vite `base` 或 `import.meta.env.BASE_URL` 解析的路径；构建后必须从真实 Pages 地址验证三张图片，而不是只看本地。

### P0：移动端横向溢出

390px 测试时页面内容宽约 436px。`Scene1Sample` 的 798 个点在进入动画前使用最多约 ±80px 的 `translate`，变换后的视觉边界越出容器；公开页底部可见横向滚动条。375/390 是任务书明确要求的核心断点。

处理：V4 不保留散射入场；样本链改为受容器裁切的单向流动表达。任何动画前后都要求 `scrollWidth <= clientWidth + 1`。

### P1：桌面存在 1px 溢出

1265px 视口实测文档宽 1266px。通常来自边框、全视口宽度或定位元素。V4 拆布局时应通过自动断点检查定位，不用全局 `overflow-x:hidden` 掩盖。

### P1：图片缺失破坏最高质量章节

安吉与黟县本来是最有现场感的材料，线上却显示 fallback；这让整页退回“数据卡 + 注释”的状态。修复路径是 V4 第一轮视觉验收的硬门槛。

## 6. 叙事诊断

用户指出的“AI 模块感”成立，原因不是个别句子生硬，而是信息架构把每一章都当成独立交付件：

1. 标题先宣布模块名，而不是制造问题或场景；
2. intro 解释组件意图；
3. 图表外围重复列出方法字段；
4. 章节末尾没有把问题递给下一章；
5. 证据边界被单独做成整页，文章最后回到审计而不是人物与地方。

V4 需要在结构层修复，不能只做“润色”。新的章节必须逐一包含 Opening、Evidence、Interpretation、Limitation、Transition，但这五项不应视觉模板化。

## 7. 视觉与动效诊断

当前“日光档案 / 调查台账”方向稳健，也避免了玻璃拟态、泛渐变和大圆角卡片。但视觉主题仍偏抽象：首屏右侧直接出现样本台账，读者先遇到研究，不先遇到移动中的人。

动效只有两个明显系统：798 点聚合和 77 节点重排。后者值得保留；前者造成移动端缺陷。当前没有 GSAP / ScrollTrigger 运行代码，ECharts 和 Visx 也没有进入当前主线。因此 V4 的动效与图表选型应视为新架构，不是假设已有实现。

## 8. V4 成功标准

- 读者能用一句话复述主线：人为什么移动，如何维持工作，又怎样与地方建立关系。
- 数据状态在代码和证据层完整，正文不再充满后台字段。
- 只有两段 sticky scrollytelling，其余靠排版、图表和短过渡完成。
- 375 / 390 / 430 / 768 / 桌面均无页面级横向滚动。
- 三张登记图片在 GitHub Pages 子路径实际加载。
- 所有图表不 hover 也能读，有静态表或等价文字 fallback。
- `prefers-reduced-motion` 下信息顺序、内容和结论不变。
- `npm run verify` 通过，且部署验证与本地验证分别记录。
