## 继续修改的执行规则

1. **以现状为起点。** 开始每一项改动前读取相关源码和 `git status`，确认用户是否又改过文件；若期间发生变化，重新读取并从新现状继续，不使用旧截图、旧文稿、旧 `chartSpecs.ts` 或 Git 恢复命令覆盖当前内容。
2. **只改登记的目标。** B4-03 修来源与有依据的文稿，B4-04 修列出的图形，B4-05 修阅读与目录，B4-06 只确定素材位置与赛事待核项。未列出的用户修正保持原样；若为解决同一问题必须牵涉其他区域，先在差异中说明理由与影响。
3. **保护删除决定。** 不恢复已删的重复数据表、无信息增量的说明、装饰横线或纯点阵。需要可访问的静态回读时，优先使用图内常显标签和同源语义内容；仅当表格增加可读事实时才增加展开表。
4. **图形服从数据关系。** 比较、构成、分支、数量和时间分别编码；不得为图形丰富度补造数据。77家是聚合样本，282人是社区渠道问卷；不同地区及不同单位不共用排名、流向或转化标尺。年份／区位／功能之间没有逐社区交叉记录，不做同一家社区跨分类身份动画。
5. **内容调整保留证据。** 收紧导语、修不明人物叙述、减少重复报数时，保留来源定位、统计对象和必要的边界句；只有可定位的人物行为才写成现场细节。直接引语逐字核对，政策目标始终标为目标。
6. **界面仍可静态阅读。** 图的核心数值、标签、来源与结论常显；手机端允许自然换行，目录入口与正文编号不能产生两套章号。动画只在 Batch 6 加入，不能使快速滚动、键盘、触摸或减弱动效模式缺失内容。
7. **验收看改动前后。** 每完成一项，检查受影响区域的旧事实是否仍在、已删冗余是否未复活，再运行适用校验和本地断点检查。页面 `clientWidth = scrollWidth` 只证明无全局溢出，还要检查图内标签、元素边界、来源定位与焦点返回。记录 PASS／FAIL 和证据；未实测不得把 Batch 4 标完成。
8. **保持批次与发布边界。** Batch 4 完成静态图表、文稿与阅读；Batch 5 审核并接入真实素材；Batch 6 处理叙事动效。当前只作为本地候选，推送、部署和线上回读另行处理。
