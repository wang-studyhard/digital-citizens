## 1. 状态词

| 状态 | 含义 | 是否可进主线 |
|---|---|---|
| VERIFIED | 已从原始或权威公开材料核对到具体值、对象、时期和定位 | 可以 |
| REPORTED | 公开预览或报道明确给出，但不是完整原始数据 / 普查 | 可以，带口径 |
| DERIVED | 用已登记数据计算得到 | 可以，明确算法和“约” |
| PENDING | 旧稿有值，但当前无法从公开原表逐格核对 | 不进入生产叙事 |
| REJECTED | 来源、口径或语义不适合本篇 | 不进入；保留审计记录 |

## 2. 恢复原则

1. 旧文件证明“曾经写过”，不证明“已经核实”。
2. `content.txt` 是最接近旧稿原始表述的本地文本，但不是原报告本身。
3. NCC 公开预览可支持样本链和若干摘要结论；完整阅读器需要登录，不能因此把本地完整矩阵标成 VERIFIED。
4. 第一轮实现只创建 `legacyCandidates.ts`；只有来源门槛通过的字段才迁入 `evidence.ts`。
5. 任何总和检查只证明内部一致，不证明外部真实性。

## 6. 实施时的数据迁移

1. 新建 `src/data/legacyCandidates.ts`，只录入本文件的 `PENDING` 候选，并带 `sourceGap`、`requiredEvidence`、`status`。

4. 图表只读取 `chartData.ts`，而 `chartData.ts` 只能从 `evidence.ts` 选择生产值。
5. `PENDING` 不得通过默认值、空值回退或旧 import 流入生产组件。
6. `REJECTED` 仅留在本审计，不进入运行包。
